# Public calendars and newsletter archives

Repository: https://github.com/AI-Innovation-2026-Fall-Group-8/ai_innovation

Branch: `feature/public-calendars-newsletters`, based on `origin/main` at
`1ccfbda`, including the newer resource page and shared header/footer.

## Install and run

Run from the top-level `ai_innovation` directory with Python 3.9+:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r tools/zot_event_crawl/requirements-public-feeds.txt
.venv/bin/python -B tools/zot_event_crawl/src/crawlers/club_crawler.py --collect-public-feeds --sources tools/zot_event_crawl/config/public_feed_sources.json --max-clubs 3 --pages-per-club 10 --from-date 2026-11-16 --until-date 2027-05-15
.venv/bin/python -B scripts/update_public_events.py
```

The collector discovers published calendar/newsletter links, imports valid ICS
occurrences and Event JSON-LD, saves readable newsletter text/event links, and
keeps unclear announcements as review candidates. The last command validates
and merges eligible events with the original ZotSpot snapshot, then atomically
writes **`data/output/unified_events.json` at the website root**. Reload the
website to see imported events. No deployment or scheduled refresh is performed.

The website uses the existing search, category, tag and time filters, chronological
ordering and day headings for these events. Source badges read “Public calendar”
and “Club newsletter.” No test fixtures are added to the real feed.

To collect from the previously discovered club directory instead:

```sh
.venv/bin/python -B tools/zot_event_crawl/src/crawlers/club_crawler.py --collect-public-feeds --club-id 33710 --pages-per-club 12
```

This defaults to the crawler's `data/clubs/club_sources.json`. Repeat `--club-id`
for several clubs; `--max-clubs` defaults to five and still caps the selection.
Without dates, collection starts seven days before today in Pacific time and
ends 180 days later. `--until-date` is exclusive; the maximum window is 366 days.

## Reusable source configuration

Input is a JSON array containing `id`, `name`, `website`, optional
`organizer_type` (`club` by default), and optional `public_sources`. Each source
has `url`, `kind`, `found_on`, `link_label`, and optional evidence. Kinds include
`calendar_feed`, `calendar_page`, `newsletter_archive`, `newsletter_feed`,
`newsletter_issue`, and `newsletter_page`.

The crawler recognizes anchors, Google Calendar iframe embeds, `webcal://`
links, and newsletter RSS/Atom alternate links. Published Google calendar IDs
are converted only to public ICS addresses. Secret/private addresses are
excluded. Links retain the club, referring page, label and collection timestamp.
A published link establishes a relationship, not independent proof of ownership.

The sample configuration contains ASME, ICSSC and Wen Public Health. The latter
is a university department, explicitly not a student club. ASME's UCI-hosted
site is used because its directory address `asmeuci.com` did not resolve. The
two club-specific ZotSpot feeds were observed in its public subscription
directory, not generated by guessing URLs.

Calendar sources receive priority. After half the request budget, queued
newsletters take priority so a large calendar cannot consume every request.
Reports list pending URLs left by page limits. Robots rules, request limits,
public-address validation and redirect checks remain active; no login, signup,
email sending, Discord access, OCR or browser-block bypass is implemented.

## Parsing and website import rules

ICS parsing uses `icalendar` and `recurring-ical-events`. It supports UTC/named
zones, date-only events, exclusive all-day ends, daily/weekly/monthly/yearly
recurrence, excluded dates, moved occurrences and cancellations. Floating times
use the calendar's declared zone or Pacific time, recorded in provenance.
Unknown named zones, non-public entries, invalid dates and high-frequency rules
stay out of the event feed. The default cap is 2,000 events per feed; reaching
it produces a review record. Source categories/tags are retained.

Newsletter publication dates stay metadata. “Next Friday,” missing years,
unstructured announcements and ordinary article timestamps never become event
dates automatically. Explicit schema.org Event JSON-LD can produce dated events;
other issues retain a raw-record ID for later extraction/review. Public event/RSVP
links are saved and followed within budget. Signup forms, generic blog/comment
feeds, unsubscribe actions and unsupported PDFs/images are not collected as issues.

The website command accepts `--base file1.json file2.json`, `--collected path.json`,
and `--output preview.json`. Inputs cannot be outputs. Use stable original/reviewed
feeds as bases, not the previous generated website feed: removed/cancelled calendar
occurrences should disappear with the fresh public snapshot. Raw text and candidate
arrays are rejected; validation completes before the website feed is replaced.

Source-issued IDs remain distinct. Cross-source duplicates require matching
title, start instant and all-day state, plus a matching event URL or organizer.
Conflicting nonempty locations remain distinct unless their event URL is identical.
Removed cross-source records are listed in the import report.

## Live sample — November 23, 2026 Pacific time

The final run attempted **22 pages across three sources**:

- ASME: its embedded Google feed was robots-blocked. Its public ZotSpot feed
  redirected to a CampusGroups static host that was also robots-blocked.
- ICSSC: the same calendar restriction; the newsletter link redirected to a
  signup form, recorded as `subscription_only`.
- Wen Public Health: **one archive index and four readable issues**, yielding
  **four review candidates**. More issues remain in the pending list.

**Zero eligible events** were extracted for November 16, 2026 through May 14,
2027. Running the import therefore retained **295 ZotSpot website events**.
The code supports accessible ICS feeds and structured newsletter events, but
this live sample does not establish access to blocked calendars or automatic
interpretation of unstructured newsletter text.

node tests/test_app.cjs

passed, including calendar/newsletter source labels, tag/search/date filtering,
